C3有一套完备的命名规则, 以防止误解, 和方便程序阅读

最基础的规则: 名称内的所有字符只包含 'a-z', 'A-Z', '0-9' 和 `_`, 且名称第一个字不可以是数字. 此外, 名称最多31个字符

### Structs, unions, enums, typedef 和 别名

所有的自定义类型以 A-Z 开头（在任何可选的起始下划线 _ 之后）, 并且至少包含一个小写字母. Bar, _T_i12 和 TTi 都是有效的名称. _1, bAR 和 BAR 则无效. 为了与 C 兼容, 可以使用属性 "cname" 将类型别名化为一个外部名称.
```c3
struct Foo @cname("foo")
{
    int x;
    Bar bar;
}

union Bar
{
    int i;
    double d;
}

enum Baz
{
    VALUE_1,
    VALUE_2
}
```

### 变量和传参

所有的变量和传参 *除了* 全局常量必须以 a-z 开头 (可选前缀`_`. `___a` `fooBar` 和 `_test_` 是有效的. `_`, `_Bar`, `X` 不是.)

```c3
int theGlobal = 1;

fn void foo(int x)
{
    Foo foo = getFoo(x);
    theGlobal++;
}
```

### 全局常量

全局常量必须以 A-Z 开头(可选前缀 `_`. `_FOO2`, `BAR_FOO`, `X` 是合规的常量命名, `_`, `_bar`, `x` 不是.)

```c3
const int A_VALUE = 12;
```

### 枚举/错误

所有用户定义的类型必须以 A-Z 开头（在任何可选的起始下划线 _ 之后）, 并且至少包含一个小写字母. Bar, _T_i12 和 TTi 都是有效的名称. _1, bAR 和 BAR 则无效. 为了与 C 兼容, 可以使用属性 "cname" 将类型别名化为一个外部名称.

enum 成员和使用 faultdef 定义的错误遵循与全局常量相同的命名标准.

```c3
enum Baz
{
    VALUE_1,
    VALUE_2
}

faultdef OOPS, LOTS_OF_OOPS;
```

### 模块

可包含'a-z', '0-9',　'_', 但是不可以有大写字母

```
module foo;
```

### 函数和宏

必须以a-z或_开头

```c3
fn int anotherFunction()
{
}

macro justDoIt(x)
{
    justDo(x);
}
```



### C3 推荐代码风格

虽然 C3 没有强制要求特定的命名风格, 但标准库仍然使用一套命名约定, 推荐用于官方绑定和标准库贡献:

```c3
alias MyInt = int;    // 类型使用 PascalCase
struct SomeStructType
{
    int a_field;      // 成员使用 snake_case
    double foo_baz;
}
int some_global = 1;  // 全局变量使用 snake_case
fn void some_function(int a_param) // 函数和参数使用 snake_case
{
    int foo_bar = 4;  // 局部变量使用 snake_case
}
// 方法使用 snake_case, 第一个参数通常称为 "self"
fn void SomeStructType.call_me(self, int a)
{
    some_function(self.a_field + a);
}
// 宏使用 snake_case
macro @some_macro(a)
{
    return a + a;
}
const MY_FOO = 123; // 常量使用 SCREAMING_SNAKE_CASE
```

简而言之:

1. 类型使用 PascalCase
2. 常量使用 SCREAMING_SNAKE_CASE
3. 其他所有内容使用 snake_case

大括号风格通常是一个有争议的话题. C3 标准库使用 Allman 大括号风格:

```c3
fn int allman(int foo)
{
    if (foo > 2)
    {
        foo++;
    }
    else
    {
        foo *= foo;
    }
    return foo;
}
```

对于 stdlib 和 vendor (官方绑定仓库) 之外的规范 C3 代码, 推荐使用 Allman 或 K&R 风格:

```c3
fn int k_and_r(int foo)
{
    if (foo > 2) {
        foo++;
    } else {
        foo *= foo;
    }
    return foo;
}
```
